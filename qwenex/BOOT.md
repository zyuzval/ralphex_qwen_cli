## Проект

**Qwenex** — это оркестратор для автономного выполнения планов разработки через Qwen CLI с системой спецификаций (BOOT/WAL/FEAT/PROP) и MCP-инструментами.

**Миссия:** Сделать автономное выполнение планов доступным с локальными моделями, структурированными спецификациями и человеческим контролем через REVIEW-маркеры.

**Стек:** Python 3.11+ · FastMCP · Qwen CLI · Git (subprocess)  
**Точка входа:** `src/qwenex/cli.py` (CLI), `src/mcp/server.py` (MCP сервер)  
**Критические ограничения:**
- Поддержка Qwen Cloud API (приоритет)
- Задел на локальные модели (Ollama)
- Задел на других провайдеров (OpenAI, Anthropic)
- Кроссплатформенность (Windows, macOS, Linux)

## Процесс обновления WAL.md

**Гибридный подход (AI + Человек):**

| Событие | Кто обновляет | Что обновляется | MCP инструмент |
|---------|---------------|-----------------|----------------|
| **Начало сессии** | AI | Номер сессии (S-NNN), дата | `wal_start_session()` |
| **Завершение задачи** | AI | ✅ Завершённые задачи | `wal_complete_task(task_id, notes)` |
| **Новая задача** | Человек | ⚡ Текущая задача | — |
| **Архитектурное решение** | AI | 🧠 ADR (DECISIONS.md) | `wal_add_adr(adrid)` |
| **Открытый вопрос** | AI/Человек | ❓ Вопросы | `wal_add_question(question, category)` |
| **Конец сессии** | AI | 📜 История сессий | `wal_end_session()` |
| **Обновление документации** | AI | Фиксация в WAL | `wal_log_change(type, description)` |

**Автоматизация:**
- AI обновляет WAL.md после каждого значимого события
- Человек утверждает изменения перед коммитом
- MCP инструменты для программного обновления WAL

**Фиксация изменений документации:**
- Все изменения в docs/ фиксируются в WAL.md
- Формат: `- [x] **[DOC-NNN: Название]** — Описание · дата`
- Связь с коммитами: git commit message содержит ссылку на WAL запись
5. docs/COMPETITORS.md — для контекста о ландшафте AI-агентов

## Принятые архитектурные решения

*Не обсуждаются, не меняются без явного решения человека.*  
*Если кажется что решение ошибочно → REVIEW-маркер, не трогать.*

| Решение | Причина |
|---------|---------|
| **Python (полностью)** | MCP SDK нативный, AI-экосистема богаче, быстрее прототипирование |
| **Один процесс (MCP внутри)** | Не sidecar — MCP как часть `src/mcp/`, проще деплой и отладка |
| **Субагенты гибридно** | 2 параллельно (quality, implementation) + 3 последовательно (testing, simplification, documentation) |
| **Qwen Cloud API (MVP)** | Основной провайдер, задел на Ollama/OpenAI через интерфейс LLMProvider |
| **BOOT/WAL/FEAT/PROP** | Глубокая интеграция — уникальное отличие от ralphex и конкурентов |
| **Трансформация планов** | Человек пишет просто → AI превращает в FEAT/PROP (v0.2) |
| **Git через subprocess** | Не dulwich — git CLI надёжнее, проще отладка |
| **REVIEW-маркеры** | AI предлагает изменения через `<!-- REVIEW: -->`, человек решает |
| **Спеки > Код** | При конфликте: Код багуется, не спека |
| **Одна задача в WAL** | Только одна активная задача в WAL.md (фокус) |
| **MVP без dmux/cmux** | Самостоятельная реализация для MVP, интеграции в v0.2 |
| **Лицензия MIT** | Совместимость с ralphex, dmux; широкое принятие |

## Протокол конфликтов

**Приоритет:** Человек > Спека (FEAT/PROP) > Код > Тесты

- Код не соответствует спеке → баг в коде
- Тест не соответствует спеке → баг в тесте
- Спека кажется ошибочной → `# REVIEW:` в коде, человеку на решение
- BOOT.md конфликтует с WAL.md → BOOT.md главнее (конституция)

## Стиль кода

- **Главный принцип:** KISS — явное лучше неявного
- **Именование:** snake_case для функций/переменных, PascalCase для классов
- **Типизация:** Обязательна (type hints), проверяется mypy
- **Документирование:** Docstrings для публичных API (Google style)
- **Тесты:** Table-driven с pytest, 80%+ покрытие
- **REVIEW-маркер:** `# REVIEW: [предложение] — причина: [почему]`
