## Шаг 2 — Единицы знания

```
[КЗ-001] Python над Go для AI-оркестраторов
Тип     : решение
Контекст: Выбор языка реализации для Qwenex (альтернатива Go как у ralphex)
Суть    : MCP SDK официально только для Python; AI-экосистема (LangChain, LlamaIndex, Ollama) богаче; прототипирование быстрее
Когда   : Оркестраторы AI-агентов с MCP интеграцией
Когда ≠ : CLI-инструменты без MCP, где критична производительность и один бинарник
Блок    : [Б-1]

[КЗ-002] Гибридное выполнение субагентов (2+3)
Тип     : паттерн
Контекст: Эмуляция параллельности без нативного Task tool у Qwen CLI
Суть    : Критичные агенты параллельно (quality, implementation), остальные последовательно (testing, simplification, documentation) — баланс скорости и ресурсов (~40% экономия vs чисто последовательное)
Когда   : Ограниченные API rate limits, ресурсные ограничения, нет нативной параллельности
Когда ≠ : Есть Task tool (Claude Code) или нет лимитов на параллельные запросы
Блок    : [Б-1]

[КЗ-003] Spec-driven Development для AI-агентов
Тип     : инсайт
Контекст: Уникальное позиционирование Qwenex относительно конкурентов
Суть    : «Почему» важнее «что» — контекст мотивации в спецификациях; при конфликте багуется код, не спека; REVIEW-маркеры для human-in-the-loop
Когда   : Автономное выполнение планов AI-агентами с человеческим контролем
Когда ≠ : Интерактивная разработка (Cursor, Cline), где человек в процессе
Блок    : [Б-3]

[КЗ-004] Task Loop with Validation (не Agentic RAG)
Тип     : модель
Контекст: Переименование архитектурного паттерна для избежания путаницы
Суть    : Plan → Analyse → Execute via MCP → Aggregate → Generate ↑ Fix Loop (max 3) — соответствует ReAct pattern, не требует vector DB/semantic search
Когда   : Оркестрация задач с валидацией и циклом самокоррекции
Когда ≠ : Semantic search, retrieval по схожести документов
Блок    : [Б-4]

[КЗ-005] MCP в одном процессе vs sidecar
Тип     : сравнение
Контекст: Архитектура MCP сервера (ADR-002, ADR-016)
Суть    : MVP: один процесс (проще деплой, нет IPC, легче отладка); Technical debt: если Qwen CLI крашнется → MCP падает; v0.2: рассмотреть sidecar
Когда   : MVP, прототипирование, стабильный CLI
Когда ≠ : Production, нестабильный CLI, нужна независимость MCP
Блок    : [Б-5]

[КЗ-006] Заимствование архитектуры без копирования кода
Тип     : паттерн
Контекст: Отношения с ralphex v0.18.0 (ADR-011, ADR-013)
Суть    : Заимствуем концепции (worktree isolation, ensureGitIgnored, 5-агентное ревью), пишем свой код на Python; лицензионная чистота (MIT → MIT)
Когда   : Референс-реализация существует с совместимой лицензией
Когда ≠ : Лицензии несовместимы (AGPL → MIT), или нужно точное поведение
Блок    : [Б-6]

[КЗ-007] Документация ≠ Прогресс
Тип     : инсайт
Контекст: 5 сессий разработки, 0% кода, только документация
Суть    : Риск «паралича документацией» — уникальное позиционирование не компенсирует отсутствие работающего продукта; нужно переходить к коду после фиксации архитектуры
Когда   : Early-stage проекты с сильной документацией
Когда ≠ : Architecture Decision Records критичны для compliance/enterprise
Блок    : [Б-1]

[КЗ-008] Fresh Context per Task
Тип     : паттерн
Контекст: Борьба с деградацией контекста в длительных сессиях
Суть    : Каждая задача = новая сессия Qwen CLI (нет накопления токенов, нет drift контекста); WAL.md хранит состояние между сессиями
Когда   : Длительные планы с множеством задач, ограниченный контекст модели
Когда ≠ : Задачи требуют общего контекста всех предыдущих решений
Блок    : [Б-4]

[КЗ-009] WORKTREE ISOLATION для задач
Тип     : артефакт
Контекст: Заимствование из ralphex v0.18.0 для изоляции задач
Суть    : git worktree add -b <branch> <path> для каждой задачи; очистка после завершения; предотвращает конфликты файлов между параллельными задачами
Когда   : Параллельные задачи в одном репозитории
Когда ≠ : Моно-задача, нет параллелизма
Блок    : [Б-6]

[КЗ-010] ensureGitIgnored паттерн
Тип     : паттерн
Контекст: Авто-коммит изменений .gitignore без загрязнения истории
Суть    : 1) Проверить .gitignore на изменения; 2) Добавить паттерны; 3) Закоммитить только если было чисто — предотвращает лишние коммиты
Когда   : Инструменты создают временные файлы/директории
Когда ≠ : Ручное управление .gitignore
Блок    : [Б-6]

[КЗ-011] REVIEW-маркеры для human-in-the-loop
Тип     : артефакт
Контекст: Контроль изменений спецификаций AI-агентом
Суть    : <!-- REVIEW: [предложение] — причина: [почему] — ждёт: решения человека --> — AI предлагает, человек решает, контекст сохраняется
Когда   : AI предлагает изменения в критичные файлы (спеки, архитектура)
Когда ≠ : Полностью автономный режим без контроля
Блок    : [Б-3]

[КЗ-012] LLMProvider интерфейс для мульти-провайдера
Тип     : паттерн
Контекст: Задел на поддержку Ollama/OpenAI без переписывания ядра
Суть    : Protocol с complete() и check_health(); QwenCloudProvider (MVP), OllamaProvider (v0.2), OpenAIProvider (v0.3); выбор через YAML config
Когда   : Нужна поддержка нескольких LLM-провайдеров
Когда ≠ : Один провайдер навсегда
Блок    : [Б-1]

[КЗ-013] Оркестраторы планов vs Ассистенты
Тип     : модель
Контекст: Позиционирование Qwenex в ландшафте AI-агентов
Суть    : 6 категорий: Ассистенты (Copilot), IDE-интегрированные (Cursor), Терминальные (Aider), Оркестраторы планов (ralphex/Qwenex), Менеджеры сессий (dmux), Платформы (Sim) — Qwenex в нише оркестраторов
Когда   : Анализ конкурентов, позиционирование продукта
Когда ≠ : Внутренняя архитектура
Блок    : [Б-2]

[КЗ-014] Гибридный процесс обновления WAL.md
Тип     : паттерн
Контекст: Баланс автоматизации и контроля (ADR-018)
Суть    : AI автоматически: начало сессии, завершение задачи, история; Человек: выбор следующей задачи, утверждение изменений; MCP инструменты для программного обновления
Когда   : Долгосрочная память проекта для AI-агентов
Когда ≠ : Краткосрочные проекты без WAL
Блок    : [Б-3]
```

## Шаг 5 — Мета-наблюдение

**Парадокс документации:** Qwenex имеет исключительно проработанную документацию (18 ADR, 6 документов архитектуры, анализ конкурентов), но 0% кода после 5 сессий разработки. Это проявляет фундаментальную проблему AI-ассистированной разработки: AI отлично документирует и планирует, но переход к коду требует другого режима работы. Уникальное позиционирование (MCP + BOOT/WAL/FEAT/PROP + REVIEW) может стать преимуществом только если будет реализовано — документация сама по себе не создаёт ценность для пользователей. Критический риск: «паралич документацией» при наличии сильного конкурента (ralphex v0.18.0) с работающим продуктом.
