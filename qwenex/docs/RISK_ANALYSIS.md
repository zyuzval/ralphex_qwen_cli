### RISK-002: Прототип Qwen CLI не проверен

| Параметр | Значение |
|----------|----------|
| **Суть** | Вся архитектура зависит от Qwen CLI, но ключевые характеристики неизвестны |
| **Вопросы** | `--output-format stream-json`? Rate limits? Стабильность? Аналог Task tool? |
| **Источник** | Kimi, Claude |
| **Влияние** | Если stream-json не работает или CLI нестабилен — требуется пересмотр архитектуры |

**Рекомендация:** Создать прототип интеграции до написания основного кода (P0).

```bash
# Проверить возможности Qwen CLI
qwen --help
qwen --output-format stream-json --prompt "test"
```

### RISK-003: MCP в одном процессе — архитектурный риск

| Параметр | Значение |
|----------|----------|
| **Суть** | ADR-016: MCP внутри процесса с Qwen CLI = single point of failure |
| **Источник** | Kimi, Claude |
| **Влияние** | Если Qwen CLI крашнется → MCP падает, вся система недоступна |
| **Текущий статус** | Отложено на v0.2 как «technical debt» |

**Переоценка:** Это не technical debt, а **архитектурный риск**. Решение: sidecar в MVP или принятие риска.

**Варианты:**
1. **Принять риск** — MVP быстрее, но ненадёжно
2. **Sidecar сразу** — надёжнее, но сложнее деплой, IPC overhead
3. **Гибрид** — MVP в одном процессе, sidecar в v0.2 с планом миграции

---

### RISK-004: Время до MVP (16-22 недели)

| Параметр | Значение |
|----------|----------|
| **Суть** | 16-22 недели против 8-12 для интеграции в ralphex |
| **Источник** | Kimi, Claude |
| **Влияние** | Конкуренты выпустят 2-3 мажорных версии, Qwenex войдёт с отставанием |
| **Причина** | Широкий scope MVP (трансформация планов, dashboard, Ollama) |

**Рекомендация:** Сократить MVP:
- ❌ Убрать трансформацию планов (v0.3)
- ❌ Убрать web dashboard (v0.3)
- ❌ Убрать Ollama (v0.2)
- ✅ Оставить: ядро, ревью, MCP базовый

---

### RISK-005: Парадокс автономности

| Параметр | Значение |
|----------|----------|
| **Суть** | Позиционирование «автономное выполнение» требует постоянного human-in-the-loop |
| **Источник** | Kimi |
| **Влияние** | Неопределённость UX — пользователь не знает, когда можно отвлечься |
| **Категория** | Не полностью автономен (ralphex), не полностью интерактивен (Aider) |

**Рекомендация:** Чётко определить режимы:
- **Автономный** — «нажал и забыл», человек только в REVIEW-маркерах
- **Интерактивный** — человек участвует в процессе

### RISK-007: MCP не конкурентное преимущество

| Параметр | Значение |
|----------|----------|
