### Шаг 2 — Единицы знания
[КЗ-001] Agentic RAG как архитектурная модель
Тип : модель
Контекст: В ревью обсуждается эволюция Qwen от LLM к agentic AI, где Qwenex использует паттерн для оркестрации задач.
Суть : Task Loop with Validation (Plan → Analyse → Execute via MCP → Aggregate → Generate с фикс-циклом max 3) как основа для автономного выполнения с валидацией.
Когда : В AI-оркестраторах для баланса автономности и контроля, особенно с мультимодальными моделями.
Когда ≠ : Не подходит для простых чат-ботов или когда нет нужды в итерациях (риск overhead).
Блок : [Б-1]

[КЗ-002] Эффективность Qwen3.5-397B-A17B
Тип : инсайт
Контекст: Анализ новых моделей Qwen для Qwenex, подчеркивающий прорыв в производительности.
Суть : Модель с 397 млрд параметров активирует только 17 млрд, обеспечивая 19x скорость на больших задачах и 60% снижение затрат по сравнению с Claude Haiku 4.5, с контекстом до 1 млн токенов.
Когда : Для экономичных agentic задач, как генерация кода/контента в Qwenex.
Когда ≠ : На слабом hardware для локального использования (требует мощного оборудования).
Блок : [Б-2]

[КЗ-003] Гибридный подход к ревью агентов
Тип : паттерн
Контекст: Обсуждение 5-агентного ревью в Qwenex как баланса ресурсов.
Суть : 2 агента параллельно (quality, implementation) + 3 последовательно (testing, simplification, documentation) для ~40% экономии времени по сравнению с чистым последовательным подходом.
Когда : В ресурсозатратных AI-системах для оптимизации API-вызовов и скорости.
Когда ≠ : При обильных ресурсах, где полный параллелизм предпочтительнее (риск сложности в логике).
Блок : [Б-3]

[КЗ-004] Заимствование из ralphex v0.18.0
Тип : сравнение
Контекст: Сравнение Qwenex с ralphex, включая заимствованные идеи без копирования кода.
Суть : Заимствовать концепции (worktree isolation, ensureGitIgnored, extended loop) для изоляции задач и авто-коммитов, но реализовать на Python с добавлением спецификаций и MCP; ralphex зрелее, но Qwenex выигрывает в контроле и расширяемости.
Когда : При разработке оркестраторов для ускорения MVP без reinventing the wheel.
Когда ≠ : Если нужна полная независимость или лицензионные ограничения (MIT совместимо, но код не копировать).
Блок : [Б-6]

[КЗ-005] Technical debt в MCP архитектуре
Тип : инсайт
Контекст: Обсуждение рисков в MVP Qwenex, связанных с интеграцией Qwen CLI и MCP.
Суть : Если Qwen CLI крашнется, утянет MCP-сервер; решение — sidecar архитектура в v0.2 для изоляции.
Когда : В монолитных AI-системах для предотвращения cascading failures.
Когда ≠ : В простых MVP, где деплой проще без sidecar (IPC overhead).
Блок : [Б-4]

[КЗ-006] BYOM и снижение затрат
Тип : паттерн
Контекст: Анализ экономики Qwenex в тренде BYOM (bring your own model).
Суть : Использовать открытые веса Qwen3.5 для локального хостинга (Ollama), снижая costs vs. платные API (Claude $1-6/млн токенов).
Когда : Для приватных/экономичных workflows в enterprise или indie-dev.
Когда ≠ : В сценариях с геополитическими рисками (зависимость от Alibaba).
Блок : [Б-5]

[КЗ-007] Тренд agentic era
Тип : модель
Контекст: Глобальный контекст перехода AI к агентам как workflow engines.
Суть : Агенты как coordinators (оркестраторы), а не чат-боты; Qwenex вписывается с MCP для enterprise (интеграция в EV-дашборды, smart glasses).
Когда : Для бизнеса в R&D, где нужна автоматизация PM-ролей.
Когда ≠ : В абстрактных задачах, где visuals или простые запросы доминируют (риск overkill).
Блок : [Б-1]

[КЗ-008] VCS абстракция в Git-интеграции
Тип : паттерн
Контекст: Описание Git-интеграции в Qwenex с возможностью расширения.
Суть : Использовать vcs_command в config для смены на hg или другие, с subprocess для надежности (не dulwich).
Когда : В кросс-VCS проектах для проще отладки и меньше зависимостей.
Когда ≠ : В чисто Git-проектах, где overhead абстракции не нужен.
Блок : [Б-4]

Готово : шаблон

```python
# src/qwenex/git_wrapper.py
import subprocess

def create_worktree(branch: str, path: str):
    """Создать git worktree для изоляции задачи"""
    subprocess.run(["git", "worktree", "add", "-b", branch, path])

def remove_worktree(path: str):
    """Удалить git worktree после завершения"""
    subprocess.run(["git", "worktree", "remove", "--force", path])
```
