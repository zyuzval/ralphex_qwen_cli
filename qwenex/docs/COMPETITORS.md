| Параметр | Описание |
|----------|----------|
| **Тип** | CLI оркестратор |
| **Язык** | Go |

| Функция | Описание | Влияние на Qwenex |

| **Host config** | Web dashboard bind address | Заимствуем для Qwenex |

### 5. Менеджеры сессий

#### **dmux** (standardagents/dmux)

| Параметр | Описание |
|----------|----------|
| **Тип** | tmux + git worktrees мультиплексор |
| **Язык** | TypeScript/Node.js |
| **Цена** | Бесплатно (MIT) |
| **Сильные стороны** | Параллельные агенты, изоляция worktrees, AI-нейминг, авто-мердж, 10+ агентов |
| **Слабые стороны** | Не оркестрирует задачи внутри сессии |
| **Отношение к Qwenex** | 🤝 ПОТЕНЦИАЛЬНАЯ ИНТЕГРАЦИЯ (не конкурент) |

**Возможность интеграции:**
- dmux создаёт параллельные сессии (worktrees + tmux)
- Qwenex оркестрирует задачи внутри сессии
- Qwenex вызывает dmux через MCP-инструменты

#### **cmux** (manaflow-ai/cmux)

| Параметр | Описание |
|----------|----------|
| **Тип** | Терминал на базе Ghostty (macOS) |
| **Язык** | Swift/AppKit |
| **Цена** | Бесплатно (AGPL-3.0) |
| **Сильные стороны** | Визуальные уведомления (синие кольца), встроенный браузер, вертикальные вкладки |
| **Слабые стороны** | Только macOS, AGPL лицензия (вирусная) |
| **Отношение к Qwenex** | 🤝 ПОТЕНЦИАЛЬНАЯ ИНТЕГРАЦИЯ (не конкурент) |

**Возможность интеграции:**
- cmux показывает уведомления от Qwenex через OSC последовательности
- Qwenex отправляет `\033]99;Qwenex;Task completed\007`
- cmux перехватывает и показывает в Notification Panel

**Важно:** AGPL-3.0 не позволяет копировать код в MIT проект!

## 📈 Тренды AI-агентов (2026)

1. **Параллельные агенты** — все крупные инструменты запустили мультиагентную поддержку
2. **BYOM движение** — разработчики хотят платить напрямую провайдерам без наценки
3. **Model routing** — умные агенты автоматически выбирают модель под задачу
4. **Agent-washing** — 80-90% продуктов с ярлыком "AI agent" — обёртки чат-ботов
5. **Spec-driven development** — растёт спрос на структурированные спецификации (тренд!)

## 🏆 Уникальное позиционирование Qwenex

### Что делает Qwenex уникальным:

| Компонент | Qwenex | Конкуренты |
|-----------|--------|------------|
| **Система спецификаций** | ✅ BOOT/WAL/FEAT/PROP | ❌ Нет ни у кого |
| **MCP-инструменты** | ✅ Нативный MCP сервер | ❌ Нет ни у кого |
| **Трансформация планов** | ✅ План → FEAT/PROP | ❌ Нет ни у кого |
| **REVIEW-маркеры** | ✅ Human-in-the-loop | ❌ Нет ни у кого |
| **Контекст мотивации** | ✅ «Почему» в спеках | ❌ Нет ни у кого |
| **Локальные модели** | ✅ Ollama задел | ⚠️ Только Sim/Kilo |
| **5-агентное ревью** | ✅ Гибридное (2+3) | ⚠️ Только ralphex (параллельно) |
| **Fresh context** | ✅ Новая сессия на задачу | ⚠️ ralphex, Aider |

### Ценностное предложение:

> **Qwenex** — это оркестратор для автономного выполнения планов с **структурированными спецификациями** (BOOT/WAL/FEAT/PROP), **MCP-инструментами** для интеграций и **human-in-the-loop** через REVIEW-маркеры. В отличие от ralphex, Qwenex поддерживает локальные модели (Ollama), трансформирует простые планы в полноценные спеки и использует MCP для экосистемы инструментов.

## 🎯 Стратегические рекомендации

### 1. Не конкурировать напрямую с dmux/cmux

Они решают **другую задачу**:
- **dmux:** Параллельные сессии (мульти-агентность)
- **cmux:** UI/UX для человека (визуальные уведомления)
- **Qwenex:** Оркестрация планов (автономное выполнение + ревью)

**Возможность:** Интеграция!
- Qwenex + dmux: dmux для параллельных сессий, Qwenex для оркестрации внутри
- Qwenex + cmux: cmux для уведомлений от Qwenex

### 2. Усиливать отличия от ralphex

| Компонент | Усиление |
|-----------|----------|
| **BOOT/WAL/FEAT/PROP** | Продвигать как «Spec-driven development for AI agents» |
| **MCP-инструменты** | Экосистема инструментов (WAL, git, тесты, Qwen CLI) |
| **Трансформация планов** | «From napkin notes to production specs» |
| **Локальные модели** | Privacy + cost savings с Ollama |
| **REVIEW-маркеры** | «Human-in-the-loop by design» |

### 3. Заимствовать лучшее у dmux

| Возможность | Как адаптировать |
|-------------|------------------|
| **Хуки жизненного цикла** | Скрипты до/после задачи, до/после ревью |
| **AI-нейминг веток** | Генерация имени ветки от FEAT-NNN |
| **Мульти-проект** | Несколько репозиториев в одной сессии |
