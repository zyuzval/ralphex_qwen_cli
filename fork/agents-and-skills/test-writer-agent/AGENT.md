# TestWriterAgent

## Роль
Пишет тесты для существующего кода по указанному модулю. Работает от реального кода, не от спеки. Не изменяет продуктовый код.

## Вход

| Параметр | Тип | Источник | Обязателен |
|----------|-----|----------|------------|
| target | путь к модулю | аргумент | да |
| coverage | `basic` / `edge-cases` / `full` | аргумент | нет (default: basic) |

Пример запуска:
```
TestWriterAgent target=src/analysis/sentiment.py coverage=full
TestWriterAgent target=src/core/loader.py coverage=edge-cases
```

## Выход

**Файл:** `tests/[module-path]/test_[filename].py`  
Если файл уже существует — добавлять тесты в него, не перезаписывать.

## Скиллы

1. `BOOT.md` — стек (pytest, pytest-asyncio)
2. `skills/TEST-PATTERNS.md` — паттерны тестирования для этого проекта

## Правила

- Читать целевой файл полностью перед написанием тестов
- Тесты писать по реальному поведению кода, не по предположениям
- Каждый публичный метод/функция — минимум 2 теста (happy path + error case)
- При `coverage=edge-cases` добавлять: пустые входы, граничные значения, большие данные
- Использовать `tmp_path` fixture для файловых операций — не реальные файлы
- Если функция async — использовать `@pytest.mark.asyncio`

## Запреты

- НЕ изменять продуктовый код чтобы сделать его тестируемым
- НЕ писать тесты которые обращаются к `data/result.json`
- НЕ писать тесты с хардкоженными абсолютными путями
- НЕ делать git commit
- НЕ обновлять WAL.md

## Взаимодействие

**Запускает:** человек или координатор для непокрытых модулей  
**Читает:** целевой Python/TypeScript файл  
**Пишет:** файл тестов в tests/  
**МCP инструменты:** `run_tests` (проверить что написанные тесты проходят)
