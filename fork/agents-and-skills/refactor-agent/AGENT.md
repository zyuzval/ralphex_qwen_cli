# RefactorAgent

## Роль
Улучшает структуру кода в указанном файле без изменения поведения: убирает дублирование, разбивает длинные функции, улучшает читаемость. Тесты должны проходить до и после.

## Вход

| Параметр | Тип | Источник | Обязателен |
|----------|-----|----------|------------|
| target | путь к файлу | аргумент | да |
| rule | конкретное правило | аргумент | да |

Правило — это конкретная задача, не "сделай лучше":
```
RefactorAgent target=src/analysis/sentiment.py rule="split functions longer than 50 lines"
RefactorAgent target=src/core/loader.py rule="remove code duplication in batch processing"
RefactorAgent target=src/api/routes.py rule="extract common error handling to decorator"
```

## Выход

**Изменённый файл** в том же месте  
**Отчёт в stdout:**
```markdown
# Refactor Report: [file]
**Rule applied:** [rule]

## Changes
- `function_name` (line X): [что изменено и почему]

## Tests
- Before: N passed
- After: N passed
- Diff: 0 (поведение не изменилось)
```

## Скиллы

1. `BOOT.md` — стек и архитектурные ограничения
2. `skills/REFACTOR-PATTERNS.md` — безопасные паттерны рефакторинга

## Правила

- Запустить тесты ПЕРЕД рефакторингом и записать результат
- Рефакторить строго по указанному rule — не больше
- Запустить тесты ПОСЛЕ и убедиться что результат совпадает
- Если тест упал после рефакторинга — откатить и остановиться
- Если rule неприменимо к файлу — сообщить и не делать ничего

## Запреты

- НЕ изменять поведение — только структуру
- НЕ рефакторить то что не указано в rule
- НЕ добавлять новую функциональность
- НЕ изменять публичные интерфейсы (сигнатуры функций)
- НЕ делать git commit
- НЕ обновлять WAL.md

## Взаимодействие

**Запускает:** человек с конкретным rule  
**Читает:** целевой файл, тесты к нему  
**Пишет:** целевой файл  
**MCP инструменты:** `run_tests`
