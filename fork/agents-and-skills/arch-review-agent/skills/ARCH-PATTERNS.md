# ARCH-PATTERNS

## Для кого
ArchReviewAgent — что проверять и как определять отклонения от архитектуры tg-stats.

## Контекст
Архитектурные решения зафиксированы в BOOT.md и PROP-001.md. Этот скилл переводит их в конкретные проверки.

---

## Принятые решения и что проверять

### Стек бэкенда: FastAPI + SQLite + Alembic

✅ Соответствует:
- `import fastapi` в src/api/
- `create_engine("sqlite://...")` в src/core/storage.py
- Миграции только через Alembic

❌ Нарушение:
- Любой другой веб-фреймворк (Flask, Django, aiohttp)
- Прямые SQL-запросы без ORM (если не указано в PROP-001)
- Миграции руками без Alembic

### Стек фронтенда: React 18 + TypeScript + Vite + Material UI

✅ Соответствует:
- `react` версии 18.x в package.json
- Все компоненты на TypeScript (.tsx)
- Стили через Material UI (не CSS-модули, не styled-components)

❌ Нарушение:
- Компоненты на JavaScript (.jsx без типов)
- Другие UI-библиотеки без явного решения
- CSS-in-JS вместо MUI

### Интерфейс: только GUI, нет CLI

BOOT.md: "GUI — веб-интерфейс в браузере, единственный интерфейс"

❌ Нарушение:
- CLI-команды в src/ для пользователя
- Argparse для пользовательского взаимодействия
- Отдельные скрипты для запуска анализа (кроме вспомогательных в scripts/)

### Загрузка: стриминг, без OOM на 1GB

BOOT.md: "Загрузка должна работать без зависаний и ошибок памяти"

❌ Нарушение:
- `json.load(open('result.json'))` — всё в память
- Отсутствие batch processing при вставке в SQLite

### Интернационализация: i18next, RU/EN

✅ Соответствует:
- Все строки в компонентах через `t('key')`
- Переводы в `web/src/locales/`

❌ Нарушение:
- Хардкоженные строки на русском или английском в .tsx файлах

### Зависимости: не добавлять без явного запроса

BOOT.md: "Не добавляй зависимости без явного запроса"

Проверять: diff `requirements.txt` и `package.json` относительно последнего коммита.  
Новые зависимости без коммит-сообщения с явным "add X dependency" — нарушение.

---

## Что НЕ считается нарушением

- Вспомогательные скрипты в `scripts/` (не пользовательский интерфейс)
- Тестовые утилиты в `tests/`
- Выбор конкретной библиотеки внутри принятого стека (например, axios vs fetch внутри React)

## UNDECIDED — решение не принято

Если нашёл что-то что кажется странным но не зафиксировано в BOOT.md/PROP-001.md — пометить как `UNDECIDED` и описать вопрос для человека. Не считать нарушением.

## Что НЕ входит в этот скилл

- Качество кода (это CODE-QUALITY.md для ReviewAgent)
- Конкретные баги (это REVIEW-PATTERNS.md)
- Предложения по новым архитектурным решениям
