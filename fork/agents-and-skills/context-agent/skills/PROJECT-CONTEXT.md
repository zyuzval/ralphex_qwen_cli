# PROJECT-CONTEXT

## Для кого
ContextAgent — как интерпретировать состояние проекта и что считать важным.

## Контекст
Сырые данные (список файлов, тесты, сессии) сами по себе не говорят что важно. Этот скилл переводит данные в оценку: на что обратить внимание человеку перед работой.

---

## Приоритеты при формировании сводки

### Critical (показывать всегда первым)
- Тесты падают (failed > 0)
- Сессия заблокирована (status: blocked) и не разблокирована
- Uncommitted changes в критических файлах (src/, tests/)

### High (показывать в quick-режиме)
- Сессии с ready_to_commit: true — ждут коммита
- Текущая задача из WAL помечена как "В ПРОЦЕССЕ" больше 2 дней
- Незакоммиченные изменения в нескольких файлах

### Medium (показывать в full-режиме)
- Pending задачи из WAL которые не начаты
- Сессии в статусе in_progress

### Low (не показывать в quick)
- Последние коммиты (только в full)
- Список всех файлов сессий

---

## Интерпретация статусов сессий

| status.json.status | Что это значит | Что делать |
|--------------------|----------------|------------|
| pass, ready_to_commit: true | Готово к коммиту | CommitAgent может коммитить |
| pass, ready_to_commit: false | Прошло но не готово | Нужна проверка человека |
| fail, iteration < 3 | Ещё пробуют | Ждать |
| fail, iteration = 3 | Заблокировано | Нужно вмешательство |
| blocked | Явная блокировка | Нужно вмешательство |
| unknown / нет файла | Сессия не запускалась | Нормально если pending |

---

## Интерпретация тестов

```
146 passed → всё хорошо
144 passed, 2 failed → показать какие упали
0 passed, ошибка импорта → критично, показать первым
```

Если тесты не запустились (например нет venv) — написать "тесты недоступны" и причину, не паниковать.
