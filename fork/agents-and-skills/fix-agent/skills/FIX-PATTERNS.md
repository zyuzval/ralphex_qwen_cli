# FIX-PATTERNS

## Для кого
FixAgent — как безопасно применять типичные исправления в этом проекте.

## Контекст
Исправление кода это не то же самое что написание с нуля. Нужно изменить минимум необходимого, не сломать соседний код, убедиться что тесты проходят. Этот скилл про безопасные паттерны изменений.

---

## Принцип минимального изменения

Всегда изменяй минимум строк для решения проблемы. Если видишь что рядом "тоже можно улучшить" — не делай это. Твоя задача из session.md, не то что видишь вокруг.

✅ Правильно (исправить только проблему):
```python
# Было: NEGATIVE_WORDS содержал 'золот'
NEGATIVE_WORDS = {"плохо", "ужасно", "золот", "отстой"}
# Стало: убрали только неверное слово
NEGATIVE_WORDS = {"плохо", "ужасно", "отстой"}
```

❌ Неправильно (заодно переделал структуру):
```python
# Взял и переделал в frozenset, добавил комментарии, поменял порядок
NEGATIVE_WORDS: frozenset[str] = frozenset({
    # Явно негативные
    "плохо",
    "ужасно",
    "отстой"
})
```

## Порядок применения исправлений

1. Прочитать session.md полностью
2. Открыть каждый указанный файл
3. Найти точное место (файл + строка из review)
4. Применить минимальное изменение
5. Сохранить файл
6. Запустить `run_tests` для этого модуля
7. Если тест упал — проанализировать, не переходить к следующему файлу

## Типичные исправления в этом проекте

### Добавление lru_cache

```python
# Было
def get_lemma(word: str) -> str:
    return morph.parse(word)[0].normal_form

# Стало — добавить только декоратор и импорт
from functools import lru_cache

@lru_cache(maxsize=10000)
def get_lemma(word: str) -> str:
    return morph.parse(word)[0].normal_form
```

Проверить после: тест на корректность лемматизации должен проходить.

### Исправление WebSocket cleanup

```typescript
// Было
useEffect(() => {
  const ws = new WebSocket(url);
  ws.onmessage = handleMessage;
}, [url]);

// Стало — добавить только return
useEffect(() => {
  const ws = new WebSocket(url);
  ws.onmessage = handleMessage;
  return () => ws.close();
}, [url]);
```

### Исправление пересечения словарей sentiment

```python
# Проверить пересечение
overlap = POSITIVE_WORDS & NEGATIVE_WORDS
assert len(overlap) == 0, f"Overlap: {overlap}"

# Убрать слова из неверного множества
# Никогда не добавлять слово в оба множества
```

### Добавление атомарной записи файла

```python
# Было
def save_wal(content: str):
    WAL_PATH.write_text(content, encoding="utf-8")

# Стало
import os
import tempfile

def save_wal(content: str):
    tmp = WAL_PATH.with_suffix(".tmp")
    tmp.write_text(content, encoding="utf-8")
    os.replace(tmp, WAL_PATH)  # атомарно
```

## Когда тест упал после исправления

**Шаг 1:** Прочитать сообщение об ошибке полностью  
**Шаг 2:** Определить — тест упал из-за моего изменения или был сломан до?

```bash
# Проверить — был ли тест сломан до исправления
git stash
python -m pytest tests/путь/к/тесту.py -v
git stash pop
```

Если тест был сломан до — зафиксировать в issues, не считать это своей ошибкой.

**Шаг 3:** Если тест упал из-за изменения — откатить ТОЛЬКО это изменение, проанализировать почему.

**Шаг 4:** Если после 3 попыток тест не проходит — статус `blocked`, описать в issues.

## Что делать с файлами которых нет

Если файл из session.md не существует:
1. Записать в `issues`: `"File not found: path/to/file.py"`
2. Продолжить с остальными файлами из session.md
3. В итоговом status.json: `ready_to_commit: false`

Не создавать файл самостоятельно если это не указано в session.md явно.
