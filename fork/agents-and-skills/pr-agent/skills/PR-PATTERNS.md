# PR-PATTERNS

## Для кого
PRAgent — как правильно описывать изменения для этого проекта.

---

## Что делает описание полезным

Хорошее описание изменений отвечает на три вопроса:
1. Что изменилось и зачем (не «что сделано» а «зачем это нужно»)
2. Есть ли что-то что может сломаться (breaking changes, зависимости)
3. На что смотреть при ревью (где скрыта сложность)

---

## По типам коммитов

### feat — что важно описать

```markdown
## What's New

### Sentiment Analysis по участникам
Добавлен dictionary-based анализ тональности для русского текста.
Каждое сообщение классифицируется как positive/neutral/negative.
Результаты агрегируются по участникам и по времени.

**Почему dictionary-based а не ML:** см. PROP-001.md §3.2
**Поддерживаемые языки:** русский (основной), английский (частично)
```

### fix — что важно описать

```markdown
## Bug Fixes

### Ложные срабатывания в negative sentiment
**Проблема:** слово 'золот' (лемма от 'золотой') попало в NEGATIVE_WORDS,
что давало неверный sentiment для сообщений типа "золотой человек".
**Исправление:** удалено из словаря, добавлена проверка на пересечение множеств.
**Затронуто:** все результаты sentiment-анализа будут пересчитаны при следующей загрузке.
```

### refactor — минимальное описание

Рефакторинг без изменения поведения — достаточно краткого summary. Не расписывать детали если поведение не изменилось.

---

## Breaking Changes — обязательный формат

```markdown
## ⚠️ Breaking Changes

### Изменён формат D3 данных графа
**Было:** `nodes: [{id, name, size}]`  
**Стало:** `nodes: [{id, label, weight}]`  
**Затронуто:** компоненты NetworkGraph, все кастомные визуализации  
**Миграция:** переименовать поля в данных
```

Если breaking changes нет — не писать эту секцию вообще.

---

## Review Notes — только реально важное

```markdown
## Review Notes

- `src/analysis/sentiment.py:89` — сложная логика определения инициатора разговора,
  стоит проверить граничные случаи (один участник, пустой чат)
- WebSocket cleanup добавлен во все компоненты кроме `ProgressBar` —
  там соединение закрывается по-другому, см. комментарий в коде
```

НЕ писать в Review Notes:
- Очевидные вещи ("изменён sentiment.py")
- Всё подряд — только реальные риски

## Формат для changelog (без PR)

Для локального проекта без remote — changelog полезен как история:

```markdown
# Changelog

## [2026-02-25]

### Added
- Sentiment analysis с поддержкой русского текста
- WebSocket прогресс-бар для загрузки файлов

### Fixed  
- Ложные срабатывания 'золот' в negative sentiment
- WebSocket утечка соединения при unmount компонента

### Changed
- Формат D3 данных: name→label, size→weight
```

- Как делать git операции
- Конвенции коммит-сообщений (это COMMIT-CONVENTIONS.md)
- Код-ревью (это ReviewAgent)
